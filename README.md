WeatherFit (입기예보)

**외출 전, 지금 날씨에 어울리는 옷차림을 한눈에 확인하세요.**

WeatherFit은 지역별 날씨를 조회하고, 체감온도와 비·눈·바람을 고려해 상의, 하의, 아우터를 추천하는 웹서비스입니다. 프론트엔드 2명과 백엔드 3명이 2주 동안 개발하는 팀 프로젝트입니다.

## MVP 기능

- **지역별 날씨 조회** — 지역을 선택해 기온, 체감온도, 습도, 강수 여부, 풍속을 확인합니다.
- **옷차림 추천** — 체감온도 구간에 따라 상의, 하의, 아우터를 골라 이미지와 추천 이유를 보여줍니다.
- **날씨별 준비물 안내** — 비가 오면 우산, 눈이 오면 미끄럼 방지 신발, 바람이 강하면 방풍 겉옷을 안내합니다.
- **반응형 화면** — 모바일과 PC에서 날씨와 추천 결과를 확인할 수 있습니다.

온도 민감도 설정은 기본 기능이 연결된 뒤 시간이 남으면 추가합니다. 기본 추천은 `보통`을 기준으로 합니다.

## 기술 구성 초안

| 영역 | 후보 |
| --- | --- |
| 프론트엔드 | React |
| 백엔드 | Node.js + Express 또는 Python + FastAPI |
| 날씨 데이터 | Open-Meteo 또는 OpenWeatherMap |
| 협업 | GitHub, VS Code |

백엔드와 날씨 API는 팀에서 확정합니다. 개발 서버 실행 명령과 필요한 환경변수는 초기 설정을 합친 뒤 이 문서에 추가합니다.

## 역할 분담

| 담당 | 작업 | 완료 기준 |
| --- | --- | --- |
| 프론트엔드 1 | 메인 레이아웃, 지역 선택, 날씨 화면 | 지역을 바꾸면 날씨가 갱신되고 조회 실패 시 안내가 표시됩니다. |
| 프론트엔드 2 | 코디 카드, 이미지, 반응형 UI | 추천 이유와 준비물이 표시되고 모바일에서도 카드가 잘 보입니다. |
| 백엔드 1 | 외부 날씨 API 연동, 좌표 처리, 응답 정리 | 좌표를 받아 기온·체감온도·습도·강수·풍속을 공통 형식으로 반환합니다. |
| 백엔드 2 | 체감온도 구간과 비·눈·바람 추천 규칙 | 날씨를 입력하면 코디와 추가 준비물이 반환됩니다. |
| 백엔드 3 | 코디 데이터 구조, API 명세, 프론트 연동, 배포 | 날씨와 코디를 한 응답으로 제공하고 배포 환경에서 조회가 동작합니다. |

## API 초안

`GET /api/recommendations?lat=37.57&lon=126.98`

기온은 ℃, 습도는 %, 풍속은 m/s로 통일합니다. 아래 응답은 프론트 개발에 사용할 예시입니다. 민감도 설정을 추가할 경우 선택 매개변수 `sensitivity`에 `cold`, `normal`, `hot`을 사용합니다.

```json
{
  "weather": {
    "temperature": 12,
    "feelsLike": 10,
    "humidity": 65,
    "windSpeed": 4,
    "condition": "rain"
  },
  "outfit": {
    "top": "긴팔 티셔츠",
    "bottom": "긴바지",
    "outer": "가벼운 재킷",
    "imageUrl": "/images/outfits/cool-casual.webp",
    "reason": "체감온도가 10℃라 가벼운 겉옷을 추천해요."
  },
  "extras": ["우산"]
}
```

## GitHub와 VS Code에서 작업하기

처음 한 번, VS Code에서 `Ctrl + Shift + P` → `Git: Clone`을 선택하고 아래 주소를 입력합니다. 복제가 끝나면 `weatherfit` 폴더를 엽니다.

```text
https://github.com/hxejeonq/weatherfit.git
```

기능을 시작할 때 VS Code 터미널에서 `main`을 업데이트하고 작업 브랜치를 만듭니다. 아래는 날씨 API 담당자 예시입니다.

```powershell
git switch main
git pull --ff-only origin main
git switch -c feat/weather-api
```

1. GitHub Issue에 작업 내용, 담당자, 완료 조건을 적습니다.
2. VS Code의 **소스 제어**에서 변경 파일을 확인하고 필요한 파일을 커밋합니다. 예시 커밋 메시지는 `feat: 날씨 API 연동`입니다.
3. `git push -u origin feat/weather-api`로 브랜치를 올립니다. 브랜치 이름은 본인 작업에 맞게 바꿉니다.
4. GitHub에서 작업 브랜치 → `main`으로 Pull Request를 만들고, 팀원 1명의 리뷰를 받은 뒤 합칩니다.

API 명세를 바꿀 때는 프론트 담당자와 먼저 맞춥니다. API 키가 들어 있는 `.env`는 Git에서 제외하고, 필요한 변수 이름만 `.env.example`에 기록합니다.
